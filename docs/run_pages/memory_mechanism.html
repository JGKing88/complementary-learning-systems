What kind of memory is this?

The recall is one matrix–vector product. It is a matched filter, not an attractor network — and that turns out to be the only regime in which the navigation signal survives at all.

The five claims

  1. This is a linear associative memory — a matched filter. Retrieval happens entirely in one product. Iterating does not improve it and actively degrades it.
  2. It works well. One step restores a cos-0.70 cue to 0.987, and the correct pattern wins 99.7% of the time.
  3. It works because of the encoder, not the memory. The encoder does two separate jobs: it separates environments, and it is a smooth chart of the arena.
  4. There are no basins, for a reason no hyper-parameter can fix. A saturating tanh has its fixed points at hypercube corners. The stored patterns are continuous vectors, which are not corners.
  5. The attractor regime exists, but it is a different network — and taking it may cost the geometry that produces the navigation signal.

What the system computes

The memory stores M patterns in a Hebbian matrix and recalls with one step:

W = (1/D) · Σk ξk ξkT        (zero diagonal)
recall(x) = normalize(tanh(β · W x))

Expanding the product is the whole story:

W x = (1/D) · Σk ξk (ξk · x)

A sum of every stored pattern, weighted by how similar it is to the cue. That is a correlation — the classical linear associative memory of Anderson and Kohonen. Nothing about it requires iteration, and §3 shows iterating makes it worse.

The encoder does two jobs; the memory does neither

Retrieval works because the encoder separates environments:

An entire environment is mapped into a tight cone and other environments are pushed to orthogonal. So the goal's term dominates the sum and one product returns it. The margin over the best distractor has median 0.862; a distractor wins in only 0.26% of cells.

Geometry is the second job, and it is what the agent consumes. Retrieval says which pattern, not where:

q = WxT (recall(x) − x)

the retrieved displacement projected onto the tangent plane of the embedding manifold. Because the encoder is a smooth chart, ξgoal − ξx ≈ Jx(pgoal − px) locally, so this recovers the grid displacement. Measured direction accuracy: cos 0.96.

Why explore and exploit are separable

A distractor lives in another environment, so the displacement to it is an unrelated direction in 1024 dimensions — and an unrelated direction keeps only √(2/D) = 0.0442 of its norm when projected onto a plane. With a displacement norm of about √2 that predicts 0.0625 against the measured 0.0670. The explore/exploit separation is a dimensionality effect, predicted from first principles, and it is free.

Why the dynamics is linear

tanh needs an argument of order 1 to bend. At 1e−4 it is the identity, so the update is normalize(W x) — power iteration.

One quantity, two knobs

The governing quantity is the loop gain β·S/D, with S = ‖p‖². Since W = (1/D)ΣppT, storing λp scales W by λ² — so β·W is exactly invariant under (p → λp, β → β/λ²), and zeroing the diagonal commutes with the scaling.

Storage norm and β are the same knob

Saying the system is linear "because patterns are stored at unit norm" picks one arbitrary half of a product. The correct statement is that the loop gain is ~1e−4, and either factor moves it.

And hopfield.beta is a no-op. With tanh linear to seven digits, normalize(tanh(βWx)) = normalize(Wx) for any positive β — the scalar cancels in the normalization. The trainer sets it from the encoder's recorded gain and it has never done anything. It would begin to matter at β ~ 10⁴.

What iterating actually does

It does reach a fixed point — a symmetric-weight system must — but the fixed point is not a memory, and getting there destroys the retrieval.

End to end on the navigation readout, cells with direction error worse than cos 0.5: 1.46% at one step, 12.27% at twelve.

steps = 1 is not an untuned default

It is the only setting that retrieves anything. Retrieval lives entirely in the first product; every later step is power iteration toward the direction most shared among all stored patterns, which by construction carries no information about which one was cued.

The memories are not attractors and the attractor is not a memory. Every stored pattern is a saddle: with symmetric W each eigenvector is a fixed point, but only the largest is stable.

Two independent conditions

Basins are made by saturation — it is what maps a whole neighbourhood onto one state. Spurious mixtures are made the same way: sign(ξ¹+ξ²+ξ³) is a fixed point precisely because sign maps it to itself. With the nonlinearity inert there is no mechanism to create any extra stable state, memory or spurious.

The current system fails the first. But it would fail the second even with the first repaired — sweeping β from 5 to 10⁶ never took stability above 0.226. Raising the loop gain converts decay into a nonzero fixed point; it cannot make a continuous vector into a corner.

What normalization actually does

It is not what prevents basins — with it still on, β = 10⁶ does produce 8 attractors. What it decides is what the degenerate attractor is: with normalization, the top eigenvector; without, the state decays to the origin.

All 11 patterns become fixed points, a corrupted cue is restored exactly, and higher gain produces the spurious mixtures classical theory predicts. The failure is a mismatch between architecture and pattern type, not a defect in the architecture. Capacity is not involved: 0.138·D = 141 against 11 stored.

That control is not perfectly clean — binarizing also decorrelates (max overlap 0.4447 → 0.2910) and moves each pattern a long way (median cos(ξ, sign ξ) = 0.7996). It shows the architecture retrieves binary patterns, not that binarizing these patterns preserves what they encode.

Where the attractor regime does live

  • Normalization does not move the boundary; the two dynamics differ only at the very edge.
  • The dynamics gain needs only 2–5× its own threshold.

Route B — change the update rule

The modern / dense associative memory update ξ ← XT softmax(βXξ) has the stored patterns as fixed points by construction, for continuous patterns: exact retrieval and exactly 11 attractors with no spurious states, stable from β = 8 through 512.

Whether you would want it

Both routes buy exact retrieval. Neither is obviously worth taking, and the reason is §1: the encoder does two jobs, and only one of them is retrieval.

The navigation signal is a geometric quantity that reads the continuous structure of the embedding. At the storage gain where basins appear (g ≥ 300) the pattern sits at cos ~0.98 to its own binarization — most of that structure is gone.

Gained

Retrieval becomes exact, so direction error attributable to recall fidelity disappears — and fidelity governs essentially all of it. Cells whose recall sits at cos ≥ 0.99 to the goal have a 0.01% rate of bad direction, and 99.7% of all bad-direction cells fall below that threshold.

Risked

The tangent projection may no longer decode direction from a saturated pattern — in which case the exactness is worthless, because direction is the only thing the policy consumes.

Route A also has an interface problem. If the stored pattern is tanh(g·ξgoal) but the cue is the raw ξx, then the displacement subtracts an unsaturated vector from a saturated one, which is not meaningful. A coherent version saturates the cue as well and re-derives the tangent basis in the saturated space — a different geometry, not a parameter change.

The decisive test, not yet run

Recompute direction accuracy and the goal-present / goal-absent ‖q‖ separation under saturated storage with matched cueing, at g ∈ {30, 100, 300}.

If direction survives, the attractor regime is genuinely available. If it does not, then the matched filter is not a limitation of this design but the only regime in which the geometry survives — the strongest statement available about the architecture.

What this says about the encoder

It does not say the encoder must produce saturable codes. That is downstream of the test above and should not be pre-empted.

It does say something independent. All retrieval failures come from the extreme tail of the cross-environment similarity distribution:

max0.9823

The mean is already perfect — the repulsion objective achieved exactly what it optimizes. The failures are rare near-collisions, where a pattern from elsewhere in the scaffold encodes almost identically to an in-environment position.

But the repel term is a mean:

repel = (K_pred[far] ** 2).mean()

Far-tail outliers contribute almost nothing to a mean-squared penalty, so there is no gradient pressure on them. Meanwhile the evaluation already uses worst-case quantities — bin_min, inner_min(R) − outer_hi(R), alias_crossing_radius.

The sweeps are scored on worst case and trained on the mean

A tail-sensitive repel term — a hinge, a top-k mean, logsumexp — would put gradient where the failures are while leaving the 99% already near zero untouched.

Two qualifications. This fixes the matched filter; it creates no basins and does not touch the dynamics regime. And whether a plain hinge suffices depends on how rare the damaging pairs are — with ~32k far-pairs per batch a threshold near 0.2 would see hundreds of violators, but if the collisions that actually break retrieval are far rarer, hard-negative mining is needed instead. That distribution has not been measured above p99.

Three faults were found and fixed while producing these, each of which had produced a confident wrong answer. A padded zero in the final step's residual read as "converged" — the opposite of what it meant. A collapsed all-zero state read as 61 distinct attractors, because normalize maps zero to zero and every pair of dead states has cosine 0. And the first storage-gain sweep used a single dynamics gain β = 1.0 and concluded nothing worked anywhere: the threshold moves with the storage gain, from 1024 at g = 1 to ~1.3 at g = 100, so a single-value control cannot test a grid whose threshold moves with the other axis.
