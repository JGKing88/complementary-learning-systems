Distractor Curriculum Run

The control spent 550 updates swinging between 3% and 100% success before it settled. Ramping the distractor count from zero to ten over the first 400 updates removes that oscillation entirely — and arrives at exactly the same place.

Success rate, against the control

Both runs are identical apart from the curriculum. The control lurches — 0.90, then 0.51, then 0.91, then 1.00, then 0.49 — and does not hold a ceiling until u600. The curriculum arm climbs monotonically from u200 and never falls below 0.99 again after u350.

The trade: a slower start

The first 200 updates are worse than the control's — 0.04 against 0.90 at u150. The curriculum is training on one or two distractors there while the control already faces ten, and the control's early spike is part of the same instability that later costs it. Breakthrough comes at u250 rather than u150, and then holds.

The curriculum changes the path, not the destination. Final performance is a wash — 11.40 steps against 10.95, and 0.948 against 0.958 at ten distractors, both inside the run-to-run oscillation. What it buys is 200 updates and, more importantly, a run that never falls apart: once it first reaches 0.85 at u300 it never touches below 0.979 again, where the control drops to 0.490 after its own breakthrough. Every collapse is a point where someone reading a single eval draws the wrong conclusion, so a run that has none is worth having even at an identical endpoint.

On the stability measure. An earlier draft of this page counted "collapses below 0.55", which was applied inconsistently — the control's count swept in its pre-breakthrough updates while this arm's did not, which flattered the curriculum. Replaced with two threshold-free facts: when a run first reaches 0.85, and the minimum it touches afterward.

It does not explain the slow convergence. The original question was why the control needs 550 updates. The curriculum answers "instability is avoidable" but still takes until u250 for its own first breakthrough, so most of the delay is something else — the sparse-reward structure is the remaining candidate, tested separately in p11_tp.
