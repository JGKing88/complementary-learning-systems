Ideal encoder · field width against kernel width · 2026-11-21

Can a code have small place fields and a wide kernel?

Yes. Give each unit a slow input and a fast input before the threshold. Fields shrink from 30 cells to 6 to 8, the population kernel stays wide, and retrieval is unchanged. The direction readout gets noisier and needs more units.

The two quantities

Field widthA property of one unit: how long a stretch of positions it fires over. Mouse dorsal CA1 fields are 0.4 to 0.5 grid periods. The current sparse ideal code has 2.5.
Kernel widthA property of the population: how far apart two positions can be and still have similar activity vectors. The memory needs this to be wide, because the similarity to a stored goal is the only signal that says which way the goal is.

The kernel is the average, over units, of how much each unit's map overlaps with a shifted copy of itself. So the two quantities come from the same single-unit maps. The question is whether they have to move together.

Why they are tied in the current code

The unit. A unit of the rotated ideal code is a threshold on a random sum of the code's waves:

s(x) = max(y(x) − t, 0),   y(x) = Σi ai cos(ωi · x + φi),   ωi ~ N(0, 1/r²)

With 512 waves the input y is close to a Gaussian random function with unit variance. Everything about it is in its correlation between two positions d apart, which is the average of cos(ω · d) over the frequency draw:

ρ(d) = exp(−d² / 2r²)

The threshold sets the share of units active, p = 1 − Φ(t), and nothing else.

The kernel uses the whole of ρ. Across units, the inputs at two positions are a pair of unit Gaussians with correlation ρ(d). The similarity of the thresholded rates is a fixed increasing function of that correlation, the same at every separation:

K(d) = Ft(ρ(d))

So the kernel falls to one half where ρ falls to a value ρ* that depends only on the threshold, and its full width there is

FW = 2r √(2 ln(1/ρ*))

The field uses only the curvature of ρ at zero. A field is a stretch where y is above a level u. Rice's formula gives the number of upward crossings of u per cell, and it depends on the input only through λ2 = −ρ″(0), the mean squared slope of y:

ν(u) = (√λ2 / 2π) exp(−u²/2)

The share of the track above u is 1 − Φ(u). Mean field width is that share divided by the number of fields per cell:

W = (2π / √λ2) (1 − Φ(u)) exp(u²/2)

For a Gaussian ρ the two are the same number. Its curvature at zero is λ2 = 1/r², so W = 2πr (1 − Φ(u)) exp(u²/2). Both widths are r times a constant that depends only on the threshold:

Pearson kernel. Field level u is 20% of the way from the threshold to the unit's peak, as in the place-field literature. Measured values match these within 4%.

Changing r scales both columns together. Changing the threshold moves the ratio only from 1.07 to 0.70, which is the factor of 1.5 that sparsity appeared to give for free. At high thresholds both widths shrink as r/t, so the ratio stops moving.

The way out is in the two formulas. The kernel depends on where ρ falls to ρ*, far from zero. The field depends on λ2, the curvature at zero. In terms of the input's power spectrum S(k), λ2 = ∫ k² S(k) dk. A Gaussian spectrum has one parameter for both. Any spectrum with a second, faster component can raise λ2 without moving the bulk of ρ.

How to separate them

Add a second, faster component to each unit's input: 70% of the variance at the slow scale (r = 23.2 cells) and 30% at a fast scale (3 cells). The fast wiggle cuts each long above-threshold stretch into short pieces, so fields are small. The unit still fires mostly in the same broad region, because the slow part decides where the input is near threshold at all. Two positions 16 cells apart therefore still share many active units, and the kernel stays wide.

With a slow share 1 − a at scale R and a fast share a at scale rs, the two formulas above become

ρ(d) = (1 − a) exp(−d²/2R²) + a exp(−d²/2rs²),   λ2 = (1 − a)/R² + a/rs²

The fast term dominates λ2 once a exceeds (rs/R)², about 2% here, so fields shrink quickly. Beyond a few cells ρ is the slow term alone, scaled by 1 − a, so the kernel only loses height in proportion to the fast share. At a = 0.3 and rs = 3 the formula gives 1/√λ2 = 5.4 cells against 23.2, and the measured field width falls from 30 to 8 cells.

The kernel's shape changes: a narrow peak sits on a wide base. Its half-height width is no longer a useful number, because the narrow peak crosses one half while the base is still there. The numbers to read are the similarity at 16 and 32 cells.

What it does to the memory

Retrieval is unchanged. Exact retrieval stays at 1.000 and the basin at 31 to 36 cells for the two-scale codes. The single-scale code with the same small fields retrieves 0.54 with a basin of 6.5. So the wide base of the kernel does the work the memory needs.

The direction readout degrades, for two separate reasons. The agent reads direction by projecting the recalled pattern minus the current code onto the change in the code over a one-cell step. A code with small fields changes a lot per cell.

  • Bias. With a forward step, the current code itself has a fixed projection on that change, equal to minus half its size on each axis. It pushes every estimate the same way and grows as fields shrink. With a 5% fast share the error is 41°, 42° and 42° at 1024, 4096 and 8192 units, so units do not help. A centred step, one cell each side, has no such term.
  • Noise. The slope of the similarity toward the goal is the same as before, but the chance fluctuations in similarity now vary over a few cells instead of over 20. A one-cell difference picks those up. They average out over units, so the error falls as about 1/√units, and holding it fixed needs units in proportion to about 1/W². Reading over ±4 cells instead of ±1 lowers it further.

Why the fast input cannot be the grid code itself

The simplest fast input would be a random projection of the grid cells. It does shrink fields (orange line above). It fails in the readout, because a sum of inputs from modules with periods 11, 12 and 13 has no wavelength longer than 13 cells and partly repeats every grid period. That repeat puts a ripple in the similarity to the goal, and a 12-cell ripple has a slope as large as the wide base's. Unlike noise, it is the same for every unit count.

The same fact explains why a random projection of the smoothed grid code gives a periodic place code. Smoothing leaves each module almost only its first harmonic (77% of its power at the production width), so the projection is close to three sine waves and correlates 0.84 with itself 12 cells away.

So both scales have to be built from products across modules, which is what the grid wave network already does for any wave.

Where the mouse target stands

Fields of 0.67 grid periods work at 4096 units. Fields of 0.52 reach 0.875 at 8192 units. By the unit law, matching the baseline's direction error at 0.5 needs roughly 16k to 32k units. That last number is an extrapolation.

Smaller fields mean more of them, because the threshold fixes how much of the arena a unit covers. In a 20-cell arena the mouse-sized code has 49% of units active and 1.55 fields per active unit, against 22% and 1.00 for the baseline.

Not done

  • Building the two-scale code in the grid wave network. A second population with faster depression is the obvious construction.
  • 16k to 32k units on the real probe.
  • The RL controller on these codes. It may tolerate a noisier direction signal than the greedy probe walk.
  • Whether to change the production readout to a centred difference. The forward-difference bias is in the agent's readout, so any small-field encoder will have it there.
